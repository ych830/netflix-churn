# 서브에이전트 오케스트레이션 원칙

(일반 대화와 단순 질문에는 적용하지 않는다.)

## 1. 직접 할지, 맡길지 먼저 판단

- 직접 처리: 주고받기가 잦은 작업, 여러 단계가 같은 맥락을 공유하는 작업, 빠른 국소 수정, 도구 몇 번이면 끝나는 작업, 속도가 중요한 작업.
- 맡김: 결과만 필요하고 중간 출력(검색 결과·원문·로그)이 길 때, 서로 독립된 갈래로 나뉠 때.
- 비용 인식: 에이전트 작업은 일반 대화의 약 4배, 다중 에이전트는 약 15배 토큰을 쓴다. 그만큼 크고 병렬화할 수 있는 작업에만 쓴다. 기본값처럼 맡기지 않는다.

## 2. 작업 유형별 에이전트 수

- 단순(사실 확인, 자료 1개): 0~1개
- 표준(비교 대상 2~3개): 2~3개
- 중간(여러 관점·방법론): 3~5개
- 대규모(항목 수십 개 수집): 5~10개. 20개를 넘기지 않는다.
- 하위 주제로 넓게 나뉘는 작업은 주제별로, 한 주제를 깊게 봐야 하는 작업은 관점별로 나눈다.
- 좁은 에이전트 여럿보다 유능한 에이전트 소수를 쓴다. 갈래 간 경계를 명확히 해 중복을 없앤다.
- 다른 갈래가 의존하는 선행 작업은 먼저 끝낸다.

## 3. 실행 순서

1. 구조 파악(직접): 원문을 다 읽기 전에 목차, 제목 줄번호, 파일 크기, 색인만 보고 나눈다. 긴 파일은 grep 등으로 필요한 줄만 추린다.
2. 병렬 실행: 독립 갈래는 반드시 한 메시지에 묶어 동시에 띄운다. 탐색은 질문당 한 번만 한다. 두 번째 탐색은 첫 탐색이 답을 못 찾았을 때만 한다.
3. 통합(직접): 최종 산출물은 내가 직접 쓴다. 사용자 폴더와 원본 파일에 쓰는 것도 나 하나뿐이다. 예외: `implementer` 는 위임 프롬프트에 적은 파일에만 쓰고, 같은 파일에는 한 번에 한 에이전트만 쓴다. 커밋·푸시는 메인만 한다.
4. 검증: 중요한 산출물만, 작성 과정을 모르는 별도 에이전트(`verifier`)가 요구사항과 근거만 보고 한 번 검증한다. 같은 결론을 재확인하는 추가 검증은 하지 않는다.
5. 중단: 같은 정보가 반복되거나, 두 번 연속 새 정보가 없거나, 답을 찾으면 즉시 멈춘다.

## 4. 위임 프롬프트 필수 항목

서브에이전트는 내 대화, 내가 읽은 파일, 설정을 모른다. 필요한 것을 최소한의 단어로 빠짐없이 쓴다.

- 목표: 핵심 목표 1개와 이 결과로 무엇을 결정하는지
- 맥락: 전체 작업에서 이 갈래의 역할, 파일 경로·줄범위, 따라야 할 규칙
- 출처·도구: 볼 곳, 믿을 출처와 피할 출처, 쓸 도구
- 범위: 해야 할 것과 하지 말 것(읽지 않을 범위, 수정 금지 등)
- 성공 기준: 무엇이 확인되면 끝인지 (테스트 명령 등)
- 출력 형식: 5번 규칙

## 5. 출력 규칙(위임 프롬프트에 항상 포함)

- 400단어 이내, 한국어 개조식
- 모든 사실에 출처 표기(파일명:줄번호, 쪽, URL)
- 원문 인용은 2줄 이내, 통째로 붙여넣기 금지
- 결론 / 근거 / 불일치·누락 / 확인 불가로 구분
- 못 찾은 것은 추정하지 말고 "확인 불가"로 적기
- 긴 결과물은 파일로 저장하고 경로와 요약만 돌려주기 (`.agent-out/`)

## 6. 모델 배정

| 일 | 모델 | 에이전트 |
|---|---|---|
| 탐색·추출 | haiku | `explorer` (기본 Explore 대신) |
| 대조·요약·초안 | sonnet | `drafter` |
| 코드 작성 | sonnet | `implementer` |
| 계획·통합·최종 판단 | 상위 모델 | 메인 |
| 검증 | 상위 모델 | `verifier` |

## 7. 금지

- 도구 몇 번이면 끝날 일을 맡기기
- 내가 이미 다 읽은 파일을 서브에이전트에게 다시 읽히기
- 서브에이전트 결과 원문을 다음 에이전트에게 통째로 넘기기
- 서브에이전트 호출을 한 개씩 따로 보내기
- 두 에이전트가 같은 파일에 동시에 쓰기
- 작성한 에이전트에게 자기 결과 검증 맡기기
- 같은 갈래의 후속 작업에 새 에이전트 띄우기: 기존 에이전트에게 이어서 요청한다.

## 8. 보고

- 맡길 때는 몇 갈래로 나눴는지 한 줄만 알린다.
- 사용자는 서브에이전트 결과를 직접 볼 수 없으므로 요약해 전달한다. 중간 결과는 나열하지 않고 최종 산출물과 미확정 사항만 보고한다.
